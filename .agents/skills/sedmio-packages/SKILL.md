# Пакеты, сборка, выпуск

Вся система — пакеты в `packages/`. Изменение доходит до машин только
пакетом из `[sedmio]` (файлы выпуска `x86_64` на GitHub,
docs/decisions.md §11).

## Два вида пакетов

- **Из файлов** (sedmio-settings, sedmio-shell, sedmio-session…): в
  `files/` лежит дерево как в системе, `package()` копирует его
  (`cp -a "$startdir/files/." "$pkgdir/"`) и выставляет права: каталоги
  755, файлы 644, исполняемые — явным `chmod 755` по списку. Новый
  скрипт без строки `chmod 755` в PKGBUILD придёт без права запуска.
- **Компилируемые** (есть `build()`): исходники в `app/` или `code/`,
  не в `src/` — её стирает `makepkg --cleanbuild`, и она в .gitignore.
  CMake + Qt 6, `qt_add_qml_module`.

Чужие проекты со своими правками (quickshell, calamares, plasma-nm,
plasma-pa, powerdevil, xdg-desktop-portal-kde) — PKGBUILD из Arch плюс
`*.patch` рядом. `[sedmio]` в pacman.conf выше Arch и CachyOS, поэтому
ставится наша сборка. Обновились Qt/KF — такие пакеты пересобирать.

## Правила PKGBUILD

- Шапка — комментарий: что это и зачем, что заменяет, откуда запускается.
  У каждой зависимости в `depends` — комментарий, зачем она.
- **Любая правка — `pkgrel` +1.** Без этого pacman на машинах ничего не
  увидит, компилируемый пакет той же версии `build-packages.sh` даже не
  пересоберёт («уже собран»), а `release-repo.sh` откажется выкладывать
  пакет той же версии с другим содержимым. Одна ветка — один подъём на
  пакет, даже если правок в нём несколько.
- Компилируемый пакет не может зависеть от наших пакетов в `depends`
  (makepkg --syncdeps ставит их из репозиториев, а там их нет). То, что
  нужно в работе (sedmio-theme и т. п.), тянет `sedmio-base`.
- Тяжёлый готовый пакет (claude-desktop) — `_prebuilt=1`: не
  пересобирается, если эта версия уже собрана.
- Новый пакет, который должен быть в системе, — ещё и в `depends`
  `sedmio-base`. На образ попадает всё, что тянет sedmio-base; только
  для live-образа — `iso/packages.x86_64`.

## Сборка

Перед сборкой выключить виртуалку (сборка и ВМ вместе — нехватка
памяти). Проверка: `pgrep -a qemu-system-x86` (без `-f`).

```sh
scripts/build-packages.sh          # всё в out/repo, подпись ключом Sedmio
FORCE=1 scripts/build-packages.sh  # пересобрать и компилируемые
JOBS=4 scripts/build-packages.sh   # меньше потоков (по умолчанию 8)
```

Пакеты из файлов собираются за секунды и пересобираются всегда.
Компилируемые — только если такой версии ещё нет. Без закрытого ключа
сборка идёт без подписи: для ISO годится, выпускать нельзя.

Проверить один пакет до выпуска (в виртуалке):

```sh
cd packages/<пакет> && PKGDEST=/tmp/pkgs makepkg -fd --noconfirm
```

Свой каталог PKGDEST, чтобы не путать с out/repo.

## Выпуск

Только когда пользователь сказал «выпусти». Порядок: ветка слита в main
→ из main `scripts/build-packages.sh` → `scripts/release-repo.sh` (нужен
`gh` со входом и ключ подписи). Скрипт сам берёт из сети неизменённые
пакеты, проверяет базу по адресу из pacman.conf и удаляет старые файлы.
Ругается «изменили, не подняв pkgrel» — поднять pkgrel названного
пакета и собрать снова. После выпуска — `sudo pacman -Syu` на машинах.

ISO собирать после выпуска (`sudo scripts/build-iso.sh`): тогда на
образе те же файлы, что в сети.

## Что сказать пользователю после выпуска

Какие пакеты и версии ушли. Что заработает не сразу: новые рамки окон
KWin (.so) — только после выхода из сеанса и входа; обновился сам
Quickshell — оболочка перезапустится. QML оболочки подхватывает хук
pacman на ходу.
