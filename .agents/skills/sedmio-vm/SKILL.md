# Проверка в виртуалке

Своя машина — рабочая: на ней не проверяют. Всё, что меняет поведение
системы, сначала в ВМ, и только потом «готово».

## Запуск и выключение

```sh
scripts/run-vm.sh --disk     # с диска out/vm/disk.qcow2 (установленная Sedmio)
scripts/run-vm.sh            # с ISO из out/iso — проверка установки
scripts/run-vm.sh --reset    # стереть диск и NVRAM
```

Диск, сокеты и ISO — в `out/` основной копии репозитория. Работаешь в
отдельной рабочей копии (git worktree) — сначала
`ln -s <основная копия>/out out`, иначе run-vm.sh создаст пустой диск.

ВМ: 4 ядра, 4 ГБ, экран 1600×900. Перед сборкой пакетов выключать:
`scripts/vm-exec.sh 'systemctl poweroff'`, ждать, пока
`pgrep -a qemu-system-x86` перестанет что-то находить. Готова ли после
запуска — `scripts/vm-exec.sh true` отвечает без ошибки.

Перед рискованным (удаление пакетов, сеанс, вход) — снимок диска при
выключенной ВМ: `qemu-img snapshot -c <имя> out/vm/disk.qcow2`
(`-l` список, `-a` вернуть).

## Команды внутри

```sh
scripts/vm-exec.sh 'journalctl -b -p warning --no-pager | tail'   # от root
scripts/vm-exec.sh --user 'quickshell ipc -p /usr/share/sedmio/shell show'
scripts/vm-exec.sh --user 'systemd-run --user --collect sedmio-store'
scripts/vm-exec.sh --push локальный_файл /путь/в/вм
```

`--user` — от пользователя uid 1000 в его сеансе (Wayland, D-Bus, тема
KDE). Переменных сеанса из environment.d там нет: программу, которой они
нужны (окно выбора файла через портал), запускать через
`systemd-run --user` — как из меню.

## Мышь, клавиши, снимок экрана

```sh
scripts/vm-input.py shot /tmp/s.png     # потом посмотреть картинку
scripts/vm-input.py click 1310 180
scripts/vm-input.py drag 400 300 1000 700
scripts/vm-input.py key meta_l print    # Win+PrtSc
scripts/vm-input.py key ctrl shift s
scripts/vm-input.py type hello.png
```

Координаты брать со свежего снимка, а не угадывать: меню и окна
сдвигаются. Шаги, которые зависят от времени (всплывающее уведомление
живёт 6 с), — одной командой: пока смотришь снимок, оно успевает уйти.

## Залить изменения

- Пакет целиком (лучше всего — проверяется то, что уйдёт людям): собрать
  (`PKGDEST=… makepkg -fd`), на хосте `python3 -m http.server 8765
  --bind 127.0.0.1` в папке с пакетами, в ВМ
  `curl -O http://10.0.2.2:8765/<файл> && pacman -U --noconfirm <файл>`.
  Большие файлы через гостевой агент не передать.
- Один файл — `vm-exec.sh --push`. Права берутся у локального файла:
  скрипт, которому PKGBUILD ставит 755, может прийти без +x.
- Оболочка и окна паролей за файлами не следят: после заливки QML —
  `scripts/vm-exec.sh /usr/lib/sedmio/shell-reload`. Без этого
  выполняется старый код, и «исправление не помогло» — неправда.

## Ловушки

- `vm-exec.sh 'systemctl reboot'` не возвращается (агент уходит вместе с
  системой, а скрипт ждёт ответа): `timeout 20 scripts/vm-exec.sh
  'systemctl reboot'`, потом ждать `vm-exec.sh true`.
- `pkill -f путь` и `pgrep -f` внутри vm-exec находят саму команду
  (путь есть в её строке). Только `pkill -x имя` / `pgrep -x`
  (имя до 15 символов). То же на хосте в циклах ожидания.
- vm-exec работает от root: каталоги, созданные им в домашней папке, —
  root'а, программы пользователя туда не пишут. После — `chown -R`.
- Без движения мыши экран тускнеет и гаснет — чёрный снимок не баг,
  сначала `vm-input.py move`.
- Qt в ВМ рисует через llvmpipe: память программ Qt Quick на 80–100 МБ
  больше, чем на видеокарте; KWin почти без эффектов (размытие, анимации
  сворачивания проверять на настоящей машине).
- Новые рамки окон KWin (.so) подхватываются только после перезахода —
  `systemctl reboot` в ВМ. Значения theme.json — на ходу.
- D-Bus-службу, которая отвечает позже (порталы), не проверять через
  `gdbus call`: он выходит сразу, и портал отменяет запрос.
- kded исполняет новый `/usr/share/kconf_update/*.upd` сразу, как файл
  появился, и помечает в `~/.config/kconf_updaterc`. Проверить «первый
  вход» — удалить ключ `done` в группе `<файл>.upd` и перезайти.
- Клавиши из `.desktop` с `NoDisplay=true` kglobalaccel при входе
  отключает, хотя залитый на ходу файл работает: проверять перезаходом.
- `kwriteconfig6 --delete` для ключа, у которого есть значение в
  `/etc/xdg`, пишет маску `ключ[$d]` — системное значение пропадает.
  Удалять строку sed'ом.
- Снимки btrfs (sedmio-update): залитое `--push` в систему, загруженную
  из снимка, после возврата пропадает.

## Отчёт пользователю

Что проверено и как (что нажато, что увидел), что не проверено и
почему. Снимок экрана смотри сам — не пиши «работает», не взглянув.
