# Разработка на самой Sedmio

Sedmio собирается на Sedmio: это Arch, поэтому сборка пакетов, ISO и
виртуалка работают напрямую, без WSL.

## Подготовка

На свежей Sedmio, от своего пользователя:

```bash
git clone https://github.com/Sedmio/sedmio.git ~/Rabota/Sedmio
cd ~/Rabota/Sedmio
scripts/dev-setup.sh /путь/к/папке/с/ключом
```

Скрипт ставит инструменты сборки, виртуалку (QEMU/KVM), `github-cli`
и Claude Code, восстанавливает ключ подписи `[sedmio]` и просит войти
в GitHub. Повторный запуск безопасен. Без папки с ключом пакеты
собираются, но выложить их в `[sedmio]` нельзя — ключ можно добавить
потом тем же скриптом.

Дальше — как в [README](../README.md): `build-packages.sh` →
`release-repo.sh` → `sudo build-iso.sh`.

## Как проверять изменения

Система разработки — она же рабочая. Поэтому:

- **Правка настроек по умолчанию** (`/etc/xdg` в пакетах) на своём
  пользователе не видна, если эту настройку ты уже менял сам: свои
  значения из `~/.config` главнее. Смотреть, что получит новый
  пользователь, — под отдельным пользователем с чистой папкой или
  в виртуалке.
- **Рискованное** (KWin, экран входа, загрузчик, ядро, драйверы) —
  сначала в виртуалке: `scripts/run-vm.sh`. Сломанный рабочий стол
  на своей машине — это и сломанное место, где его чинят.
- **Подсмотреть настройку.** Поменять что-то мышкой в «Параметрах
  системы» и посмотреть, что изменилось в `~/.config`
  (`ls -lt ~/.config | head`) — так находится ключ, который нужно
  положить в пакет.

Изменения доходят до своей машины так же, как до всех: выпуск в
`[sedmio]` и `sudo pacman -Syu`.
